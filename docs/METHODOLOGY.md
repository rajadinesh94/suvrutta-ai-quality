# Evaluation method

## Deterministic stage and outcome suite (v3)

Python/pytest is the primary stage harness. `datasets/v3/stages.json` contains three original fictional adult-owned sources in text, Markdown, and JSON formats and five labeled retrieval queries. The standalone lexical pipeline checks parsing, chunk boundaries/overlap, source and revision provenance, term postings, duplicates, updates, deletion, staged failure recovery, and owner filtering before ranking. Recall@k, precision@k and reciprocal rank are computed from declared source IDs; the convention for an expected empty result is recall and precision 1.0 only when nothing is returned. The sample is too small for broad quality or latency claims. Paraphrase failure is documented as a lexical limitation, not mislabeled as semantic success. OCR and embeddings do not exist in this reference target and are marked not applicable.

`datasets/v3/outcome-controls.json` supplies a baseline structured observation and five mutations for missing approval, unsupported citation, cross-user access, invented detail, and duplicate writes. The outcome oracle checks write receipts, owned source IDs, citation IDs and labeled facts. These are task-level proxies. A real product adapter must collect receipts and source ownership from trusted application boundaries; generated text alone cannot establish a write or disclosure. The local cycle also turns on a test-only owner-filter bypass, requires the corresponding Python cross-user test to fail, removes the fault, and reruns the full supported suite. The provisional acceptance thresholds are versioned before comparison in `config/budgets.v1.json`.

## Live conversational suite (v2)

The `datasets/v2/` splits contain 20 new original fictional multi-turn cases. They do not alter the 38 v1 reference cases (30 executable and eight unevaluated). The live runner sends full conversation history to a named loopback endpoint, with an explicit maximum call count and per-call timeout. `--role-mode user-assistant` folds system instructions into the first user turn only when the endpoint cannot accept a system role. This transformation is recorded in the mode and config hash. A repeated case starts with a fresh conversation; it is not a within-session continuation from the previous repeat.

Each turn's declared literal checks are narrow string assertions. They are appropriate for a known date, place, or planted fictional canary string, but cannot prove broad faithfulness, completeness, uncertainty, privacy, or safe tool handling. A case with no checks is still a live observation and remains pending semantic judgment. All cases receive a pending human label even if literal checks pass. Critical literal failures or provider errors fail the generated-text gate; otherwise the gate remains incomplete until human review. A repeated planted canary is a model-output failure, not proof that another user's stored content was disclosed. The endpoint exposes no tool execution or ACL trace, so actual side effects and cross-user access remain unverified.

The runner hashes code, prompt, v2 dataset, contracts and non-secret config before sending any request. It records target and role mode, complete fictional turns, per-turn duration, literal failures, errors, reported model and usage/cost. Unknown usage or cost is `null`, not zero. Repeats report distinct reply sequences and literal status agreement; small repeats are descriptive variability evidence, not a confidence interval. Complete run files are ignored; checked-in examples must be redacted summaries.

Two independent human reviewers use the frozen run and the case rubric. Each scores faithfulness, uncertainty and action safety from 0–2. `npm run calibrate` counts pending pairs, disagreements, exact agreement and Cohen's kappa per dimension. Kappa is `null` when undefined. Disagreement requires adjudication outside the tool; labels are never silently replaced. Reviewer agreement measures consistency, not truth or expertise. No human labels are currently asserted in this repository.

The `datasets/v1/` JSON files have separate development and held-out regression splits. Each case records ID, fictional provenance inherited from its dataset, workflow, input, initial state, permitted evidence, mock tool responses, expected facts, prohibited actions, severity, rubric, and executable steps. The held-out split is separate for regression discipline, not secret. A change to target behavior should preserve IDs when intent is stable, add a new version when expectations change, and explain any removals.

Each step invokes the pure reference engine and checks exact status, error code, source count/text, draft text, clarification presence, story count, or duplicate receipt. The paired-revocation case repeats retrieval before and after revocation. The negative control activates a deliberate defect only in a test run and requires exactly the expected paired-revocation and consent-restored failures, with no unexpected failures. No average can override a critical privacy/action failure. Reports group by workflow, risk, and severity with sample counts and individual durations; these small deterministic samples have no statistical model variance. Judge errors cannot pass because no judge is run. Future model-judge output must include model/version, rubric, temperature, prompt hash, raw verdict, error state, and human calibration sample.

Human review is pending. A reviewer should independently score a frozen sample across source faithfulness, uncertainty, relevance, completeness, and harmful action, then compare agreement by category and adjudicate disagreements without changing hidden labels mid-run. Record reviewer qualification and date without personal data. Until that occurs, do not claim expert validation.

Synthetic traces show tool name, actor fixture label, argument field names and hash, status, code, duration, and before/after story count and consent state. A plain hash is not anonymization for low-entropy private input; private adapters must omit or protect such values. They avoid full input text and hidden reasoning. Local run reports are ignored; keep only reviewed, redacted summaries in version control. A private integration should hash or redact source content, avoid vault plaintext and credentials, document retention, and obtain appropriate consent. Token and cost fields are zero because no model executes. A live run must measure usage or mark it unknown, never silently replace unknown with zero.

The browser wrapper records a new run ID, timestamp, target, mock mode, selected browser projects, relative command, hashes, measured duration, exit status, counts, classified failure types, and zero model usage/cost. Raw Playwright JSON and traces stay in that ignored run folder; the provenance summary omits absolute paths and input content. Flaky browser tests are investigated by reproducing the failure and comparing trace, server response, and state transition. Assign an owner, link a specific issue, and record quarantine expiry if a temporary quarantine is necessary. Do not add fixed sleeps or retries to conceal a defect. CI uses no retries; failed tests block the run.
